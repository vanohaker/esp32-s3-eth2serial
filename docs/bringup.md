# План первого аппаратного испытания

2026-10-11 выполнена первая прошивка и часть испытаний: запуск, память, DHCP,
HTTPS, SSH по паролю, отказ второй SSH-сессии, реальная перезагрузка через веб
и сохранение настроек/идентичностей. Точный объём — [в отчёте](verification.md).
Serial пока физически не подключён; передачи данных и форматирования карты не было.
Пункты ниже остаются полным планом, а не списком завершённых проверок.

1. Проверить маркировку/схему платы, 16 МБ flash, 8 МБ PSRAM, питание и конкретный
   USB-порт. Первую загрузку сделать без RS-232-кабеля к целевому устройству.
2. Сохранить исходный дамп устройства, если на нём есть нужная прошивка. Прошить
   собранные образы по `build/flash_args`, открыть USB-консоль для диагностики.
   При пустой конфигурации проверить вход `admin` / `admin` и отсутствие пароля в логе.
3. Проверить старт без microSD: HTTPS и SSH должны работать, ошибки карты не должны
   сбрасывать NVS. Проверить сохранение пользователей и настроек после отключения питания.
4. Проверить DHCP, статический адрес, отключение и возврат Ethernet. При потере линка
   активная сессия должна отпустить UART; после возврата требуется новый вход.
5. До подключения MAX3232 сделать TTL loopback GPIO16↔GPIO17. Проверить SSH с паролем,
   ключами Ed25519/RSA/P256, неверными ключами и паролями. Проверить, что SSH exec,
   subsystem, port forwarding и второй SSH-канал не дают обхода эксклюзивности.
6. Включить Telnet. Проверить вход и переход консоли, байты `0xff`, `0x00`, CR/LF,
   клиент без binary negotiation. Проверить две сессии одного протокола и SSH+Telnet.
   В каждый момент данные к UART должны поступать только от одного владельца.
7. Удалить loopback, проверить MAX3232 по функциям выводов, соединить с консолью
   целевого устройства. Начать с параметров консоли, подтверждённых его документацией.
   Проверить реальные уровни, прямой/null-modem кабель и согласование GND.
8. Проверить малую FAT-карту: загрузка, удаление, повторная загрузка, потеря связи
   во время upload, заполненная карта, повреждённая ФС, извлечение и перезапуск.
   Подтвердить, что ошибка mount не стирает карту. После подтверждённого форматирования
   проверить новое монтирование и сохранность настроек во внутренней flash.
9. На совместимом приёмнике проверить XMODEM checksum/CRC и YMODEM: пустой файл,
   1 байт, некратный блоку размер, больше 256 блоков, потерянные ACK, отмена с обеих
   сторон, переставший отвечать приёмник. Для YMODEM сравнить точный размер и SHA256;
   XMODEM может сохранять дополнение `0x1a`, так как размер файла не передаётся.
10. Во время upload/transfer/format попытаться перезагрузить, форматировать повторно
    и выполнить заводской сброс: конфликтующие команды должны отклоняться.
    Проверить, что после отказа устройство не остаётся в состоянии Shutdown.
11. Проверить VLAN на заранее настроенном tagged-порту коммутатора: DHCP, ARP,
    HTTPS, SSH, MTU 1496. Например, ICMP payload 1468 без фрагментации для IPv4.
    Убедиться, что трафик другого VID и untagged не открывает управление.
12. SMTP: сервер доступен сразу, появляется позже, отключается во время отправки;
    multiline-ответы и ошибки адресата. При успехе одно письмо за загрузку, без секретов.
13. Проверить BOOT: менее 10 секунд ничего не меняет; более 10 секунд с отпусканием
    сбрасывает только namespace `knife`. Проверить новую пару ключей и вход
    `admin` / `admin` без вывода пароля в USB;
    удостовериться, что файлы карты сохранены.
14. Длительный тест SSH + HTTPS + microSD с наблюдением heap, стека задач, UART overflow
    и потребления питания. После этого повторить с PoE. Измерить размер и скорость
    загрузки веба по реальному Ethernet, а не по локальному браузерному тесту.

Ограничения прототипа для этих испытаний: нет горячей замены карты, нет индикации
сброса RGB-светодиодом, нет аппаратного/программного flow control и BREAK, нет ZMODEM.
При проблемах сохранять USB-лог без пользовательских секретов.

## Прошивка из WSL2 через Windows

На первом стенде WSL2 не видел `/dev/ttyACM*`, но Windows обнаружил плату как COM3.
Использован официальный [esptool 4.12.0 для Windows](https://github.com/espressif/esptool/releases/tag/v4.12.0):
`esptool-v4.12.0-windows-amd64.zip`, без установки Python или изменения системы.
SHA256 архива сверён с метаданными релиза:

```text
42fddc5e6a05716868ad77fb43acbf53be041f97abed87ff850df1dc88140889
```

В примерах ниже `esptool.exe` и файлы находятся в текущем каталоге Windows.
При запуске из WSL передавать Windows-пути к образам; COM3 относится только к
проверенному стенду и перед новой прошивкой должен быть идентифицирован заново.
Проверенные операции:

```powershell
.\esptool.exe --chip esp32s3 --port COM3 --after no_reset flash_id
.\esptool.exe --chip esp32s3 --port COM3 --after no_reset get_security_info
.\esptool.exe --chip esp32s3 --port COM3 --baud 921600 --after no_reset read_flash 0x0 0x1000000 before-first-flash.bin
.\esptool.exe --chip esp32s3 --port COM3 --baud 921600 --after no_reset write_flash --flash_mode dio --flash_freq 80m --flash_size 16MB 0x0 bootloader.bin 0x8000 partition-table.bin 0x40000 eth2serial.bin
```

Последняя команда сохраняет NVS. Для первичного перехода со сторонней прошивки
сначала проверить её таблицу разделов и сохранить дамп. На первом экземпляре
новая область NVS `0x9000..0x38fff` пересекалась со старыми данными, поэтому была
отдельно инициализирована. Не добавлять очистку NVS в обычное обновление.
Адреса и параметры записи всегда сверять с актуальным `build/flash_args`.

На этом стенде некоторые переключения RTS/DTR оставляли ESP32-S3 в ROM-загрузчике.
Для выхода использован сброс watchdog из esptool после очистки только временного
бита `FORCE_DOWNLOAD_BOOT` по адресу из реализации
[ESP32-S3 в esptool 4.12.0](https://github.com/espressif/esptool/blob/v4.12.0/esptool/targets/esp32s3.py):

```powershell
.\esptool.exe --chip esp32s3 --port COM3 --after watchdog_reset write_mem 0x6000812c 0x0 0x1
```

Это операция над регистром RTC с маской, не запись eFuse. Она относится к
проверенной модели и версии инструмента; не переносить адрес на другие ESP32.
Открытие COM3 через `System.IO.Ports.SerialPort` тоже может перезапустить плату,
даже с заранее заданными `DtrEnable=false` / `RtsEnable=false`. USB-монитор
115200 8N1 следует открыть до сетевых проверок и не переоткрывать во время них.
Пароль больше не выводится в USB: при пустой конфигурации действуют заводские
данные входа из README. Журналы старых сборок могли содержать одноразовый пароль.
