# Аппаратный профиль прототипа

Плата: Waveshare ESP32-S3-ETH, PoE-модуль Waveshare. Пользователь сообщил, что
маркировки ревизии нет; MAX3232 пока не подключён, RTS/CTS отсутствуют.
Источник распиновки — [схема производителя](https://files.waveshare.com/wiki/ESP32-S3-ETH/ESP32-S3-ETH-Schematic.pdf),
дата на листе 2024-12-21, и [описание платы](https://docs.waveshare.com/ESP32-S3-ETH).
Первое включение и проверка встроенного Ethernet выполнены 2026-10-11.
Разводка внешнего MAX3232 и линии microSD ещё требуют физической проверки.

| Интерфейс | GPIO | Настройка |
| --- | --- | --- |
| W5500 MOSI / MISO / CLK | 11 / 12 / 13 | SPI2, 20 МГц в прототипе |
| W5500 CS / INT / RESET | 14 / 10 / 9 | Штатная разводка платы |
| microSD MOSI / MISO / CLK / CS | 6 / 5 / 7 / 4 | SPI3, отдельная шина |
| UART1 TX / RX | 16 / 17 | Выбраны для внешнего MAX3232, физически пока не соединены |
| BOOT | 0 | Вход, активный низкий уровень |
| USB D− / D+ | 19 / 20 | Штатный USB, консоль USB Serial/JTAG |
| RGB LED | 21 по опубликованной разводке | В этой версии не используется |

По документации: ESP32-S3R8, flash 16 МБ, PSRAM 8 МБ, W5500 по SPI. У W5500
используется MACRAW и стек lwIP ESP-IDF. Для VLAN предусмотрена программная обработка
802.1Q; доступ через нетегированные кадры при ненулевом VID не разрешён. Теги QinQ
не поддерживаются. MTU снижен до 1496, чтобы добавленный тег укладывался в буфер
драйвера. При аппаратных испытаниях проверить DHCP, ARP, TCP и граничные размеры кадров.

При первой прошивке esptool определил ESP32-S3 (QFN56), ревизию **кристалла v0.2**,
flash Winbond 16 МБ и встроенную PSRAM 8 МБ. Прошивка подтвердила Octal PSRAM 80 МГц
и успешный тест памяти. USB Serial/JTAG обнаружен в Windows как COM3
(VID:PID 303A:1001). Это не подтверждает ревизию PCB. W5500 получил адрес по DHCP;
реальные HTTPS и SSH работают. microSD вернула `ESP_ERR_TIMEOUT` при инициализации,
автоматическое форматирование не запускалось. Подробные результаты —
[verification.md](verification.md).

PoE-модуль заявлен производителем как IEEE 802.3af. Использовать совместимый
коммутатор/инжектор. Совместимость с пассивным PoE не предполагается. Доступный бюджет
питания конкретного модуля и потребление сборки с картой ещё не измерены; прошивка
не управляет согласованием PoE. Подключать MAX3232 только после проверки питания
и назначения выводов модуля. Не использовать питание RS-232-стороны как питание GPIO.

Для микросхемы [MAX3232 Texas Instruments](https://www.ti.com/product/MAX3232)
допускается питание 3–5,5 В, но изготовитель и обвязка имеющегося модуля неизвестны.
Для ESP32 необходимы сигналы TTL-стороны 3,3 В; рекомендация — модуль с подтверждённой
работой от 3,3 В. Маркировка `TX/RX` у переходников неоднозначна: проверять функцию
T1IN/R1OUT по документации или разводке, а не соединять одинаковые надписи вслепую.

GPIO0 — загрузочный вывод. См. [режимы загрузки ESP32-S3](https://docs.espressif.com/projects/esptool/en/latest/esp32s3/advanced-topics/boot-mode-selection.html).
RESET соединён с EN и не используется для измерения длительности нажатия.
